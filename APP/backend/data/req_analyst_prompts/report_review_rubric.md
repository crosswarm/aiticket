# 探索报告质量评审规则

## 完整性标准
- 每个菜单节点必须标注探索状态（深探/概览/未探索）
- 功能树必须覆盖所有一级菜单分组
- 每个深探页面必须记录：布局模式、工具栏按钮列表、列头/字段列表、数据量
- 截图必须与文字描述一一对应，截图索引表不能遗漏

## 深度标准
- 深探页面的工具栏必须列出每个按钮的名称和功能说明
- 表单/弹窗必须记录每个字段的类型（text/select/checkbox/date）和是否必填
- 配置面板必须逐 Tab 记录内容
- 数据量、分页信息必须用具体数字

## 证据链标准
- 每个功能判断必须有截图编号佐证
- 技术发现必须提供 DOM 选择器或 class 名
- 数据样本必须引用真实值（如流程编码 Proc_xxx）

## 一致性标准
- 多 Agent 交叉审查时矛盾点必须列出并裁定
- 同一实体在不同章节的描述不能自相矛盾
- 数据量差异需标注原因（时效差异/权限差异）

## 结构标准
- KB 文档必须有 YAML frontmatter（title/category/tags/explored_at）
- findings 必须包含：概览、导航路径、功能树、各应用详述、对标矩阵、截图索引
